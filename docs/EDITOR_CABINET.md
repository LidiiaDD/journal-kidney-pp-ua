# JRS — запуск захищеного кабінету редактора

## Що вже є в коді

- `/admin/login` — приватний вхід, лише за email/password через Supabase Auth.
- `/admin` — список приватних чернеток і опублікованих матеріалів.
- `/admin/articles/new` — форма нового рукопису.
- `/admin/articles/<id>` — редагування чернетки, додавання PDF і окрема команда «Опублікувати».
- `/publications` — публічно показує **лише опубліковані** матеріали.
- `/publications/<slug>/pdf` — видає PDF через сервер лише після перевірки публікаційного статусу.

**Статус:** окремий проєкт Supabase JRS створено, міграції застосовано, а `JRS_SUPABASE_URL` і `JRS_SUPABASE_PUBLISHABLE_KEY` додано у Production Vercel. Вхід очікує створення власного редакторського акаунта, додавання його UUID до `jrs_editors` і перевіреного повторного розгортання Vercel.

## Активація (один раз)

1. **Виконано:** створено окремий Supabase-проєкт `journal-of-renal-science` (ID `olezcakvtuhdrpbvqmwy`). Не використовуйте бази інших проєктів.
2. **Виконано:** створено таблиці `jrs_editors`, `jrs_articles`, приватне сховище `jrs-pdfs` і політики RLS, у тому числі вибіркове читання PDF уже опублікованих статей. SQL-код збережено у `supabase/jrs_schema.sql`.
3. У **Authentication → Users** створіть особистий обліковий запис редактора. Вимкніть публічну самореєстрацію, якщо вона ввімкнена. Використовуйте сильний унікальний пароль та доступну в акаунті багатофакторну перевірку.
4. Скопіюйте **UUID** саме створеного користувача з Authentication → Users. У SQL Editor виконайте (підставте фактичний UUID):

   ```sql
   insert into public.jrs_editors (user_id)
   values ('00000000-0000-0000-0000-000000000000');
   ```

   Тут нулі — **приклад, а не справжній UUID**. Ніколи не запускайте його без заміни.
5. **Виконано:** у **Vercel → journal-kidney-pp-ua → Settings → Environment Variables** уже додані змінні для Production:

   | Key | Meaning |
   | --- | --- |
   | `JRS_SUPABASE_URL` | HTTPS project URL, e.g. `https://example.supabase.co` |
   | `JRS_SUPABASE_PUBLISHABLE_KEY` | Publishable API key (`sb_publishable_...`) |
   
   Секретний ключ **не потрібний** для оприлюднених PDF: доступ до них контролюється правилами RLS. Не додавайте ключ із повними правами до змінних сайту. Після внесених налаштувань потрібне нове успішне розгортання Vercel.
6. Після створення вашого редакторського акаунта, безпечного додавання саме його UUID і розгортання перевірте вхід на `https://journal.kidney.pp.ua/admin/login`. До цього моменту доступ залишатиметься закритим.

## Оновлення редакційної роботи (жовтень 2026)

- На сторінці збереженої статті є **«Переглянути оформлення»**: приватний попередній перегляд із тим самим макетом, що й публічна стаття. Незбережені зміни форми в перегляді не відобразяться — спершу збережіть чернетку.
- PDF можна **замінити, поки стаття залишається чернеткою**: новий файл отримує власну приватну адресу, а запис статті посилатиметься на новий файл. Старий файл залишається у приватному сховищі як непов'язаний об'єкт до окремого очищення.
- Перед публікацією потрібно підтвердити **всі чотири перевірки**: згоду авторів, відповідність етичним вимогам, захист персональних даних і достовірність метаданих/файлу. Сервер перевіряє підтвердження незалежно від інтерфейсу.
- Час публікації, редакторський UUID і результати перевірок зберігаються в записі статті. Додано обмеження бази, яке не дозволяє перевести матеріал у статус `published` без цих значень.
- Публічна сторінка статті має блок **«Як цитувати»**: читач може скопіювати бібліографічне посилання або постійну адресу. DOI й номери випусків не вигадуються.
- **Автоматичного збереження полів форми наразі немає.** Користуйтеся кнопкою «Зберегти чернетку» перед переходом на іншу сторінку. Це свідомо залишає повний контроль над текстом у захищеному сховищі.

## Двомовні метадані та бібліографія (жовтень 2026)

- У редакторському кабінеті оберіть **основну мову статті**. Її назва, анотація та ключові слова залишаються обов'язковими.
- За бажанням внесіть **перевірений переклад другою мовою**: усі три поля разом (назва, анотація, ключові слова). Частковий переклад не зберігається. Сайт **не перекладає** тексти автоматично.
- У полі **Список літератури** вносіть один перевірений бібліографічний запис на рядок (не більше 150). Бібліографію система не вигадує і не доповнює.
- Укажіть лише фактично наявні **том, випуск, сторінки**. DOI додавайте тільки після реєстрації: сайт перевіряє синтаксис, але не підтверджує реєстрацію DOI автоматично.
- На публічній сторінці з'явиться перемикач мови метаданих, якщо якісний переклад додано. Пошук у каталозі враховує обидві мови.
- Стилі **Vancouver (спрощений)** та **APA (спрощений)** — машинно сформовані варіанти із наданих метаданих, а не гарантія дотримання вимог конкретного видавництва.
- Читач може копіювати посилання, цитування та експортувати **RIS** чи **BibTeX** для Zotero, Mendeley та інших менеджерів. Імена авторів у бібліографії беруться точно в тій формі, в якій внесені редакцією.
- Чинні опубліковані статті залишаються незмінними: нові поля необов'язкові, редакція не підмінює раніше опубліковані записи.

## Тематичний атлас журналу

- Публічна сторінка `/topics` — тематичний атлас нефрологічних досліджень. Вона показує лише реально опубліковані матеріали та фактичні лічильники.
- Кожна тематична картка переходить до архіву з фільтром `/publications?topic=...`. Там можна додатково вибрати тип публікації та виконати повнотекстовий пошук за метаданими.
- Класифікація автоматична, за назвою та ключовими словами українською й англійською. Це **не редакційна оцінка якості**. Одна стаття може входити до кількох тематичних груп.
- Якщо стаття не підходить до жодної спеціалізованої групи, вона відображається у «Інших дослідженнях» і не зникає з каталогу.
- Перелік напрямів та критерії автоматичного віднесення зберігаються в `app/lib/research-topics.ts`. Для точного розподілу під час оформлення статті додавайте коректні наукові ключові слова; не створюйте фіктивних публікацій задля заповнення плиток.

## Щоденний сценарій роботи

- Увійдіть до кабінету редактора.
- Натисніть **Нова стаття**, вкажіть назву, латинський slug, тип, мову, авторів, анотацію та ключові слова.
- Збережіть **чернетку** — вона ще недоступна читачам.
- За потреби додайте затверджений PDF. Поточне обмеження — **3,5 МБ** на файл для роботи в межах стандартного серверного завантаження Vercel; для більших PDF потрібен окремий механізм прямого захищеного upload.
- Перевірте біоетику, згоду авторів і відсутність персональних даних пацієнтів у PDF.
- Лише після перевірки натисніть **Опублікувати статтю**. Стаття з'явиться в каталозі, PDF стане доступним через контрольований маршрут.
- Опубліковані записи надалі не редагуються через цей інтерфейс; для виправлень необхідна окрема редакційна процедура із журналом змін.

## Безпека

- Облікові записи НЕ створюються через інтерфейс кабінету.
- Паролі перевіряє Supabase Auth, а не код сайту.
- Роль редактора зберігається в таблиці `jrs_editors`, не в email або `user_metadata`.
- RLS забороняє стороннім редагувати статті та бачити чернетки.
- Усі PDF зберігаються в **приватному** бакеті.
- Сервер публічного PDF спершу перевіряє публічний запис `status = published`, а вже потім читає PDF. Для публічного PDF використовується ключ із мінімальними правами та RLS, а не серверний ключ із повним доступом.
- Якщо налаштування відсутні, кабінет **fail-closed** і не пропускає на сторінки редактора.
- HTTP-only cookies із SameSite=Lax використовуються для сесії. Авторизація перевіряється на сервері кожної дії.
- Слід забезпечити резервні копії Supabase; GitHub не є архівом неопублікованих рукописів.
- Не завантажуйте неанонімізовані дані пацієнтів. Сам факт розміщення в приватному сховищі не замінює належних правових підстав для обробки медичних даних.

## Перевірка після активації

1. Без входу `/admin` переадресовує на `/admin/login`.
2. Акаунт без запису в `jrs_editors` не може ввійти, прочитати чернетки чи завантажити PDF.
3. Новий рукопис залишається приватним: не відображається в `/publications` і `/sitemap.xml`.
4. Після окремого рішення «Опублікувати» стаття з’являється в публічному каталозі.
5. Читач може завантажити PDF опублікованої статті; PDF чернетки не можна отримати без права редактора. Перелік об'єктів сховища анонімно не відкривається.
6. Після виходу приватні маршрути більше не відкриваються.

## Обмеження поточної версії

Наразі немає багаторольового процесу рецензування, автоматичного перетворення DOCX на PDF, лічильників переглядів, DOI/ISSN, повноцінного версіонування статей чи самостійного відкликання публікацій. Ці функції потрібно планувати окремо, коли редакційний процес стабілізується.
