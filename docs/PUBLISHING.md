# JRS — як додавати наукові публікації

## Статус і контроль якості

Journal of Renal Science — незалежний науково-інформаційний онлайн-журнал.
Сайт **не** заявляє статус фахового видання, DOI, ISSN чи індексацію, яких ще немає.

Додавайте **лише вже погоджені до публікації** статті. До розміщення:
- перевірте авторські права та згоду всіх авторів;
- переконайтеся, що стаття відповідає редакційній політиці;
- перевірте відсутність ПІБ пацієнтів, дат народження, номерів медкарт та інших ідентифікаторів у PDF;
- для клінічних випадків отримайте необхідні дозволи/інформовану згоду;
- перевірте точність анотацій, статистики, опису методів та афіліацій;
- якщо автор є членом редакційної ради, організуйте незалежний розгляд і позначте зв’язок з редакцією.

## Опублікувати статтю

1. Підготуйте фінальний PDF без персональних даних пацієнтів.
2. У GitHub відкрийте `public/`. За потреби створіть каталог `publications/` і завантажте файл, наприклад `ckd-biomarker-study-2026.pdf`.
3. Відкрийте файл `app/lib/publications.ts` і додайте запис у масив `publications`. Зараз масив навмисно порожній, оскільки не було надано готових дозволених до публікації статей.
4. Збережіть зміни. Після оновлення сайту стаття з’явиться в каталозі `/publications`, а її постійна сторінка — за адресою `/publications/<slug>`.
5. Перевірте сторінку, відображення на телефоні, дату, пошук і доступність PDF. Якщо додано DOI, перевірте його реєстрацію та перехід.

### Приклад запису — лише шаблон, не публікувати як реальну статтю

```ts
{
  slug: "approved-renal-study-2026",
  title: "Точна затверджена назва дослідження",
  publishedAt: "2026-10-25", // ФАКТИЧНА дата оприлюднення
  type: "original-research",
  language: "uk",
  authors: [
    {
      name: "Повне ім'я автора",
      affiliation: "Підтверджена установа, місто, країна",
      orcid: "0000-0000-0000-0000" // Тільки справжній ORCID; інакше вилучити
    }
  ],
  abstract: "Повна перевірена анотація дослідження.",
  keywords: ["Хронічна хвороба нирок", "Біомаркери"],
  pdfUrl: "/publications/ckd-biomarker-study-2026.pdf"
  // doi: "10.xxxx/..." — додавати лише після фактичної реєстрації
},
```

**Примітка:** це демонстрація структури даних у документації. Вона не включається до публічного каталогу.

Обов’язкові поля: `slug`, `title`, `publishedAt`, `type`, `language`, `authors`, `abstract`, `keywords`.

Тип статті (`type`) може бути:
- `original-research` — оригінальне дослідження
- `review` — оглядова стаття
- `case-report` — клінічний випадок
- `brief-report` — коротке повідомлення
- `perspective` — аналітична стаття

Опційні поля: `pdfUrl`, `doi`, `volume`, `issue`, `pages`, `affiliation`, `orcid`.

**Slug** — короткий унікальний латинський ідентифікатор зі знаків `a-z`, цифр та дефісів. Не змінюйте його після опублікування, інакше зламаються посилання.

## Що вже працює

- Каталог `/publications` із пошуком за назвою, авторами, анотацією та ключовими словами.
- Фільтрація за типом матеріалу, коли статті додані.
- Сортування за датою: найновіші спочатку.
- Автоматичне створення персональної сторінки для кожної статті.
- Виведення авторів, афіліацій і ORCID за наявності.
- Анотація, ключові слова, дата, тип публікації, мова, необов’язкові том/випуск/сторінки.
- Кнопка PDF лише тоді, коли в метаданих задано PDF-файл.
- Виведення DOI лише за наявності підтвердженого значення.
- Адаптивна верстка для телефону й комп’ютера.

## Що ще НЕ реалізовано

- Немає кабінету редактора або форми завантаження PDF з браузера: додавання зараз виконується через файли GitHub та нове розгортання.
- Немає автоматичної перевірки відповідності PDF метаданим чи персональних даних.
- Немає системи рецензування та електронного документообігу.
- Немає автоматичної реєстрації DOI, ISSN або включення до наукометричних баз.
- Після подання авторами через email рукописи не публікуються автоматично.

Для PDF з великим розміром або для редакційного завантаження без доступу до коду згодом варто створити захищену адміністративну панель та приватне сховище чернеток. **Не** завантажуйте неопубліковані рукописи в публічний GitHub-репозиторій.
